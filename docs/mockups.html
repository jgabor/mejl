mejl UI mock-ups

These are design mock-ups for mejl, a planned terminal email client for Fastmail. They are not screenshots of working software. Every screen is drawn on a fixed grid of monospace cells, the way ratatui draws a terminal frame, so each layout could be built as shown.

The layouts follow the UX spec sketch in terminal-ux.md. The rules screen reflects what fastmail-rules-sieve.md found possible today, and the Masked Email screens follow fastmail-masked-email.md. All names, addresses and companies in the grids are fictional.

Page keys: 1 to 9 jump to a screen, t toggles the theme.

How to read the grids

The grids use the default terminal theme idea from the spec: the 16 ANSI colours, bold for unread, dim for previews and hints, and one background for the cursor row. In a plain 16-colour theme the cursor row would be reverse video. The dark theme is the default. The light theme shows how the same ANSI roles read on a light terminal.

State never depends on colour alone. Every state has a glyph or a word. Indicator glyphs come from the Unicode "Neutral" width class, which terminal-ux.md checked, so they stay one cell wide in CJK locales. Box drawing is the one exception the spec accepts. A real build ships an ASCII fallback set.

Mouse support cannot be seen in a still grid, so each caption lists what is clickable. The rule from the spec holds everywhere: every mouse action has a key, no action needs the mouse, and every clickable label shows its key.

1. Inbox, wide layout

Design choices

  • Three panes at 160 columns or more: mailboxes, conversation list, reader preview. At 100 to 159 columns the sidebar becomes an overlay (screen 8). Under 100 columns it is a single stack (screen 7).
  • One row per conversation, with a message count after the sender. Rows: selection, unread, pin and mask markers, sender, subject, dim preview, date.
  • The date column is a fixed 6 cells so rows never jitter: a time for today, a weekday for this week, "Oct 3" for this year. Older mail would show the full date.
  • Saved searches are local to mejl, because Fastmail's saved searches have no public JMAP surface. Rules and Masked Email sit in the sidebar as tools.
  • The status line shows the selection counter and sync state. "Synced via JMAP push" means the EventSource stream is open and the last StateChange was caught up with /changes. The list always renders from the local cache.

Keys

j/k move, o or Enter open, x select, X range, * then a/n all or none, y archive, d trash, s pin, m move, r/a/f reply, reply all, forward, z undo, Tab next pane. These match Fastmail's web shortcuts.

Mouse

  • Click a row to select and preview it. Double click opens it. Click the marker column to toggle selection.
  • The wheel scrolls the pane under the pointer. The thumb on the list border shows the position.
  • Drag either vertical border to resize panes. The ratio is saved.
  • Click a mailbox, a hint in the bottom bar, or right click a row for the actions menu (the same menu as ;).

2. Reader with Masked Email panel

Design choices

  • Read messages fold to one line. The newest message is expanded. Quoted text folds to a marker line, and " toggles it.
  • The HTML part is converted to styled text (html2text rich mode): the heading in bold, the table as aligned columns, and links as numbered footnotes listed at the end. OSC 8 links are an optional extra on top.
  • Remote images stay off. Fastmail only proxies images in its own apps, so loading them here would expose the user's IP address. O opens a sanitised copy in the browser.
  • The side panel shows which masked address received the message: its description, site, state, and a local message count. mejl matches To and Cc against the cached MaskedEmail/get list. The X-FM-Masked-Email header can help once its value is confirmed by a live test.
  • "Sender matches the site" is a phishing hint: mail from an unrelated domain to a shop's mask gets a warning instead.

The disable flow

One key, @, opens the disable confirm in the status line, as in this grid. The confirm is deliberate: disabling sends all future mail to Trash silently, password resets and receipts included. y disables, and an undo toast appears; z sets the mask back to enabled. The other mask actions are follow-ups in the same prompt: d deletes the mask (mail bounces) with a stronger confirm, r starts a rule, m lists all mail to the address.

The Masked Email doc suggested a bare x here, and terminal-ux.md has @ as a general mask actions key. mejl keeps x for select, as in Fastmail, and makes @ a prompt that leads with disable. Copying the address moved to the global Y copy menu, because y answers the prompt.

Keys and mouse

j/k next or previous conversation, n/p message, e expand, L links overlay, H full headers, u back. Click a footnote number or URL to open or copy it, click a fold marker to toggle it, click the attachment to save it, and click any side panel action.

3. Compose with identity and mask picker

Design choices

  • The From picker lists identities and aliases, then offers a new masked address for the recipient's domain. It also shows whether a mask has been used with this recipient before.
  • The new mask is created with state enabled, not pending. Fastmail deletes pending masks after 24 hours if no mail arrives, which would break an address the user just handed out. mejl requires a description, and sets forDomain to the recipient's site.
  • The picker says plainly that sending as a mask over JMAP is untested. The web app can do it, but whether Identity/get lists masks or EmailSubmission/set accepts one is unknown. Until a live test passes, this is a design goal.
  • The body uses a built-in editor with markdown, sent as HTML plus a plain text part. The draft autosaves to Drafts through Email/set, and the status line shows its age.

Keys

Tab/Shift-Tab next or previous field. Ctrl-o is the compose prefix: s send, a attach, m new mask, e edit in $EDITOR, p preview, d discard. Ctrl-s saves. Ctrl-Enter sends on terminals with the kitty keyboard protocol, or tmux with extended keys, and is never the only way. Esc leaves the field, and a second Esc closes compose and keeps the draft. Alt keys are left out on purpose, because over SSH and tmux they can arrive as Esc plus a letter.

Mouse

Click a field to focus it, click a picker row to choose it, and click an attachment's remove hint. The body is a normal text field. Hold Shift to select text natively in kitty and Ghostty.

4. Command palette and search

Palette

  • : or Ctrl-k opens it. One fuzzy list covers commands, mailboxes, saved searches, contacts, rules and masks. Matched letters are highlighted.
  • Every row shows its key binding, so using the palette teaches the shortcuts. Ranking mixes the fuzzy score with how often the user runs each command.
  • The screen behind it is drawn with the terminal's dim attribute, which ratatui supports. Nothing here needs transparency.

Search

  • / takes Fastmail search syntax. mejl parses it into chips and shows the exact JMAP filter it sends, so the query is never a black box.
  • Local results arrive first from the cache. Server results from Email/query merge in after, each row labelled with its source.
  • Fastmail's to: covers To, Cc and Bcc, but JMAP's to filter matches only the To header. mejl ORs the three filters to keep Fastmail's meaning.
  • Enter turns the results into a normal list view, and Ctrl-s saves the search locally. Click a row to open it, or a chip to edit it.

5. Rules manager (Sieve)

What is possible today, and how the screen shows it

  • Fastmail has no public API for rules or Sieve. Its Sieve FAQ says the only way to change the script is the web interface, and it offers no ManageSieve. No API token or documented OAuth scope covers rules. A private web-client API exists, but Fastmail's API Developer Policy forbids "using unpublished APIs", so mejl does not touch it.
  • So mejl owns its rules and renders one marked Sieve block. P copies the block to the clipboard (OSC 52) and opens Settings, Filters & Rules. The user pastes it into the custom section directly below spam protection, replacing the old block. The banner and the "paste status" box make this manual step visible at all times.
  • mejl cannot read the server script, so "on Fastmail" says unknown. v lets the user paste the section back, and mejl checks the markers and the hash for drift.
  • Fastmail's own UI rules are not listed. The JSON export and import route is untested, so this screen does not pretend to read it.
  • The "where the block runs" order, and the target section below spam protection, come from third-party samples of the generated script, not from Fastmail's docs. Fastmail's help page describes four editable areas while the samples show three, so the box says the order is unconfirmed and mejl names the target by position, never by number.
  • If a Fastmail session ever advertises urn:ietf:params:jmap:sieve (RFC 9661), P becomes a direct upload and the banner goes away. mejl would still only edit its own marked region.

How the block is written

  • Begin and end markers with a hash. No require line, since Fastmail generates it, and only extensions that appear in Fastmail's require line.
  • fileinto :mailboxid with the folder name as fallback (RFC 9042), so a rename does not break the rule.
  • A disabled rule renders as if false #, the Roundcube pattern, so mejl can parse its own block back.
  • Never keep (a forum report says it breaks alias folder delivery) and never discard (it bypasses Fastmail's backups). stop is off by default, with a warning that it would also skip Fastmail's own rules, notifications, calendar handling and vacation replies.
  • The dry run checks mejl's block with a local Sieve parser against cached mail. It cannot simulate Fastmail's generated blocks. "Apply to existing" uses the documented Email/set and can be undone.

Keys and mouse

n new, F new from a message (in the reader), Enter edit, Space on or off, J/K reorder, t dry run, a apply to existing. Click a rule to edit it, click a condition to change it, drag the borders to resize, and click any hint.

6. Masked Email manager

Design choices

  • One MaskedEmail/get with ids: null loads every mask into the cache. mejl refreshes on demand, after its own writes and on a timer, then diffs locally. Reports say /changes does not work for masks, and push coverage is unknown, so the status line says when the last full refresh ran.
  • States use a glyph and a word: ✓ enabled, ✗ disabled (mail goes to Trash), ◦ pending (hidden in Fastmail's UI and deleted after 24 hours), and - deleted (mail bounces, restorable). Like Fastmail, the default filter hides pending and deleted. Here the user has turned them on with 3 and 4.
  • The message count and sender list come from mejl's own index, because the API has no message link. ! marks a mask that got mail from a sender unrelated to its site.
  • createdBy is set by the server, so masks made by mejl show its token or OAuth client name.
  • Fastmail publishes no creation limits. On a rateLimit error mejl says Fastmail limits how many masks can be created and offers an existing mask for the same site. It never shows a "remaining" count.

Keys

/ search address, description and site, 1 to 4 toggle state filters, n new (description required, created enabled), e enable, x disable with confirm and undo, D delete with a stronger confirm, r rename, Enter show messages, y copy, R make a rule for this address. A used mask cannot be destroyed, so delete always means state deleted.

Mouse

Click a column header to sort, click a filter chip to toggle it, click a row to show its details, and double click to list its messages.

7. Narrow layout, 80 by 24

How the inbox collapses

  • Under 100 columns mejl uses one pane. The sidebar hides behind g or a click on "Inbox ▾". Enter opens the reader full width, and u or Esc comes back.
  • The preview text goes first, then the selection column, which only appears while a selection is active. The date column keeps its fixed width.
  • The hint bar keeps the most used keys and ? shows the rest. Below 20 rows the hint bar can be turned off.

Why it matters

Many users run a mail client in a tmux split or over SSH on a small window. The same keys work at every width, so muscle memory carries over from the wide layout.

8. Which-key popup after a prefix

Design choices

  • The user pressed g. A prefix key does nothing on its own, so mejl never waits on a timeout. The popup lists the follow-up keys at once, and the status line shows the pending prefix.
  • Esc cancels. A key that is not listed cancels too, and does nothing else.
  • The same popup appears for every prefix: . mark, * select, and Ctrl-o in compose. @ in the reader is a prompt instead, because it leads with the disable confirm (screen 2).
  • This grid also shows the middle breakpoint: at 120 columns the list and the reader share the screen and the sidebar is an overlay.

Mouse

Click an entry to run it. Click outside the popup to cancel.

Grid check

When the page loads, a script checks every grid. Each row must hold exactly the declared number of cells, no text may be clipped at a pane edge, and only ASCII, box drawing and the safe glyph set may appear. It also measures each rendered row against the cell width, which catches glyphs that fall back to a wider font. Results go to the browser console and appear below.

What these mock-ups cannot show

  • Speed. The goal is that mejl's own work fits in one frame (p99 under 8 ms) for local actions, with no waiting on the network. A still picture cannot show that.
  • Hover, drag and click behaviour. The captions describe them instead.
  • Your terminal's font and palette. A real build uses them, so colours and glyph shapes will differ.
